## Первый срез

1. Через утверждённый API отдать канонический набор и принять/сохранить структурно корректный план. До готовности ядра расчёт не выдаёт нулевой или «успешный» результат: отсутствующий метод либо 501/NOT_IMPLEMENTED.
2. Соединить операции W2 availability → W1 physical → W2 costs → checks в один вызов. Сценарные преобразования выполнять один раз. На первом реальном синтетическом плане подключить W4.
3. Сохранить/открыть вход, версию источника, предпосылки, результат и версию алгоритма; отдать CSV из того же результата. Повторный расчёт тех же входов должен воспроизводить числа в согласованном допуске.

## Полный backend

Согласуй с W4 ресурсные операции: case, расчёт, получение результата по ID, проекты save/list/open/import и export. Имена маршрутов закреплены G1, не создавай несовместимые альтернативы. Различай повреждённый ввод (422), неизвестный ID (404), конфликт обновления (409), ошибку расчёта и корректно рассчитанный план с нарушенными ограничениями. Последний не превращать в 500 и не исправлять скрыто.

JSON-проектам — уникальные ID, проверка версии при обновлении, атомарная запись и защита от одновременной потери правок; тест двух запросов к одному проекту. Не использовать общий глобальный «текущий план» и `last_result` для всех пользователей. Пользовательское имя не становится произвольным файловым путём. Прототип — один backend worker, без распределённого хранилища; ограничения описать. Не блокировать health длительным CPU-циклом в async event loop.

Сохраняй происхождение исходников, выбранные правила времени/дисконтирования, scenario/plan ID, units и версию модели. Потерянная предпосылка при импорте — диагностика, не default. Для изменённого плана прежний результат имеет другую ревизию и не считается текущим.

CSV/XLSX: исходники/план, yearly balance, source schedule, inventory trace, расходы, service, checks, риски и сравнения, когда эти блоки реализованы. Пустой risk register не выдавать за завершённое исследование. Не пересчитывать финансы в экспортере. Настроить размер входов/ответов и безопасную выдачу файлов.

## Проверки

- Повреждённый JSON, неизвестная версия/ID, path traversal в имени, нечисловые значения, два параллельных пользователя и конфликт обновления.
- Save → reopen → recalculate → export; входы и числа согласованы. Изменение плана не подхватывает чужой сохранённый результат.
- API-тесты FastAPI TestClient/HTTPX + pytest; минимум `uv run --locked pytest tests/api tests/integration -q` после появления этих тестов.
- Генерация OpenAPI и TypeScript повторяема; сгенерированные типы не править руками.
