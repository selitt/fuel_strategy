# Контракты: актуальная реализация и дальнейшее согласование

Работающий математический контракт находится в `src/app/dto/calc_dto.py`; базовый HTTP-контракт Васи — `src/app/api/KosmoAPI.yaml`. Расширенный HTTP-контракт для frontend генерируется из приложения в [docs/api/openapi.json](../docs/api/openapi.json). DTO веб-обёрток находятся в `src/app/dto/web_dto.py`.

Замена расчётного адаптера и владельцы — [TEAM_AND_NEXT](../docs/api/TEAM_AND_NEXT.md). Произвольные исходные наборы/CSV/XLSX, параметры новых источников и будущие периоды ещё нужно согласовать с владельцами модели. Наличие поля в JSON не доказывает, что движок его использует.

# Общие контракты данных · согласовать в T01

Это **семантический проект**, не утверждённый API и не реализация.
Читать вместе с [словарём организатора](../fuel-hackathon/test_oil/docs/DATA_DICTIONARY.md),
[plan.schema](../data/schemas/plan.schema.json) и
[export.schema](../data/schemas/export.schema.json).
Исходные схемы намеренно неполны: массив произвольных objects не проверяет даты, единицы, мощности и смысл решения.

## Сущности и границы

| Сущность | Содержание | Важное различие |
|---|---|---|
| CaseData | Спрос, каналы, storage, investments, ограничения, версия/хеш источника | CASE_INPUT, не редактируемые решения |
| Plan | ID, заказы, резервирование, инвестиции, политика запасов и выдачи | TEAM_DECISION, не сценарий среды |
| Scenario | ID, статус, период/параметр/изменение, правила сочетания | BASE/mandatory отдельно от TEAM_* |
| AssumptionSet | Имя, смысл, значение/единица, источник/основание, область действия, статус | Неизвестное не заменяется значением по умолчанию |
| CalculationRequest | CaseData/version + Plan + Scenario + AssumptionSet + версия алгоритма | Достаточно для повтора расчёта |
| CalculationResult | Баланс/история, график источников, финансы, сервис, проверки и provenance | Не генерируется интерфейсом или LLM |
| SavedProject | Входы/ссылки на неизменяемые версии, решения, предпосылки, версии схем/алгоритма | Открытие восстанавливает те же условия |

## Обязательный смысл полей

Согласовать единые названия с единицами. Мощность `reserved_capacity_t_per_year` — не тоннаж `ordered_t`/`delivered_t`/`served_t`.
Поле `reserve` без определения недопустимо: физический запас и право на будущую поставку различаются.
Плановая, оплачиваемая, ожидаемая, доставленная и выданная величины не объединяются в одно число.

У заказа нужны источник/контракт, объём, дата принятия решения/заказа и предполагаемого поступления.
У резерва мощности — мощность, договорный период и условия. У инвестиций — решение, платежи, ввод, эффект и зависимости.
Точный формат календаря и единиц определяет T01 после Q03/Q04/Q05; здесь нет скрытого выбора дневного шага.

Данные результата должны обеспечивать минимум организатора:
`scenario_id`, `plan_id`, `units`, `assumptions_reference`, `yearly_balance`,
`source_schedule`, `inventory_trace`, `financial_breakdown`, `constraint_checks`, `risk_register`.
При необходимости дополняются версиями и сравнением сценариев; формат экспорта остаётся CSV/XLSX по постановке.

Диагностика: ID правила, сценарий/план, период, источник/объект, фактическое значение, порог, единица,
причина и уровень. Для неприменимой/невычисленной метрики явное состояние, не 0.

## Как закрепить контракт

В T01 описать типы, обязательность, допустимые диапазоны, межполевые проверки, идентификаторы, даты,
сериализацию, версионирование и миграции сохранённых планов.
Составить минимальный структурный пример без выбранной конкурсной стратегии.
Проверить с владельцами физики, экономики и интерфейса. Изменение общего контракта — согласуемое изменение для всех потребителей.
