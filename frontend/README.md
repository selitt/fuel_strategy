# Frontend — следующий этап, реализация ещё не начата

Стек команды: React + TypeScript + Vite; визуализация по необходимости. Backend готов к подключению через HTTP, однако это не подтверждение математической модели.

[API и запуск](../API_README.md) · [Роли и последовательность](../docs/api/TEAM_AND_NEXT.md) · [Полная OpenAPI](../docs/api/openapi.json)

Основной путь: шаблон/импорт JSON → редактор плана → сохранение проекта → расчёт → годовые таблицы и нарушения → сравнение → экспорт. Все расчётные значения приходят от backend; клиент не копирует формулы.

`GET /api/meta` описывает возможности и ограничения; `GET /api/catalog` — read-only справочники организатора, не контракт пользовательского набора данных. Для полей ввода использовать DTO из OpenAPI. Учитывать `prototype/unverified`, `not_calculated/current/stale`, `origin=imported`, ошибки `422/409/500/503`. В отсутствие рядов запасов/рисков показывать отсутствие данных, не нулевые результаты.

Vite по умолчанию запускается на 5173 — localhost и 127.0.0.1 уже разрешены CORS. Импорт использует FormData с полем `file`, без ручного Content-Type. Перед JSON/Blob проверять HTTP-статус ответа. `Content-Disposition` доступен для имени выгрузки.

Здесь пока нет `package.json`, генератора TypeScript-клиента, компонентов или Dockerfile UI. Их добавляет владелец frontend, не разработчики математики. Не привязывать установку backend к наличию этих файлов.

Текущая передача backend и точки подключения: [HANDOFF](../docs/api/HANDOFF.md). OpenAPI остаётся единственным источником типов; количество тестов подтверждается только фактическим запуском.
