# Правила проекта для Codex и других агентов

## Контекст и режим

Кейс: **«Топливный космоконтур 2035»**, команда из 5 человек.
Текущий комплект содержит реализованный frontend, рабочий HTTP API и исходный прототип движка. Математическая приёмка и проверка сетевой production-сборки не завершены. Актуальная передача UI: `docs/frontend/HANDOFF.md`, фактические проверки: `docs/frontend/TEST_REPORT.md`. Исторический backend handoff: `docs/api/HANDOFF.md`.
Не решать задачу ВКД, «Космос как инфраструктура», прогноз нефтяного рынка или Fuel Labs.
Стек расчётного приложения и форма интерфейса утверждены частично: Python/FastAPI/Pydantic + React/TypeScript/Vite/Plotly + Docker Compose, без Streamlit на старте. Solver, ставка, календарная реализация, владельцы и сроки остаются открытыми: `docs/decisions.json`.

Сначала прочитать `START_HERE.md`, `docs/PRODUCT.md` и **одну выбранную карточку** из `tasks/`.
Затем только связанные первоисточники и контракты. Не перечитывать все исторические заметки вместо работы.
Глобальное «изучи/спланируй» не означает «реализуй всё». При запросе только каркаса не создавать бизнес-логику.

Сохранять терминологию, правила и ограничения источников.

## Неподвижные смысловые правила

Critical demand входит в total. Capacity, reserved, ordered, paid, delivered, inventory и served не одно число.
Годовых сумм недостаточно для внутригодового дефицита/переполнения. Календарь и порядок событий общие для модулей.
Физический запас неотрицателен; shortage отдельно. Потери один раз на валовое поступление;
holding cost по среднему физическому запасу с учётом времени.
Физический45-дневный резерв проверяется на начало каждого года по спросу сценария.
Предзапас имеет источник/дату/оплату, подготовительный период и расходы; он не бесплатен.
Мощность Emergency сама по себе не запас: проверить покрытие ожидания поставки6недель.
BASE детерминирован: reliability не автоматический множитель объёма.
TOP учтён в max(order, share*reserved_period); reservation отдельно; нет повторных месячных TOP-минимумов поверх годового.
Earth-New90+270=360 всего. ZBO не начисляется дважды из двух CSV. Launch уже включён в цену канала.
Mandatory: спрос×1.15 с2038 по2040; variable Core/Flex×1.25 только2038–2039, исходная цена2040;
Lunar фактические доли.55/.75/1 без повторной reliability.
Loss ceiling≤2% с2038 — проверка, НЕ автозамена коэффициента потерь.
Не отменять оплату ISRU автоматически при недопоставке.
BASE/mandatory/low-high/свои риски изолированы; адаптация не отменяет оплаченные обязательства и время реакции.
Стоимость без выручки не называть прибылью. Статистику/вероятности не придумывать.
Подробности и источники — `docs/regulation/RULES.md`.

## Архитектура и границы работы

Один контракт и единое ядро для источников/сценариев. UI и экспорт используют результат ядра, а не копии формул.
Числа плана в `plans/`, настройки в `configs/`, не жёстко вшиты в алгоритмы.
Имена будущих функций/каталогов — соглашение команды, не обязательный стек организатора.
Не создавать fake app.py, функции с нулевыми ответами, фиктивный optimizer или заранее выбранную стратегию.
Фикстуры — только явно SYNTHETIC/NOT_CALCULATED, не как итоговый результат.

Одна задача — один согласованный scope. Общие contracts/календарь/зависимости менять с владельцами потребителей.
Секреты, ключи, credentials, личные .env и режимы обхода разрешений не добавлять.
Не менять глобальные настройки Codex и не требовать установленного необязательного плагина.

## Проверка и честная готовность

`python3 tools/workspace.py check` и `python3 -m unittest discover -s tests/workspace -v`
проверяют КАРКАС. Windows: `py -3` вместо `python3`.
Они не запускают модель, не означают V01–V10 и не подтверждают K01–K20.
`python -m pytest -q` проверяет HTTP/хранение/выгрузки и целостность workspace; `python tools/export_openapi.py --check` выявляет устаревшую OpenAPI. Эти проверки не доказывают математическую корректность. `tests/acceptance/catalog.json` — отдельная конкурсная приёмка.

Для новой реализации сначала независимый тест/эталон, затем код, фактический запуск и сравнение.
Нельзя подменять тесты `assert True`, чтением ожидаемого результата как фактического,
скрытым skip/xfail или редактированием контрольных исходников.
Служебный `test_oil/tools/validate_reference_repo.py` проверяет комплект организатора и запрещает там приложение.
Его нельзя перенести как готовый CI участника. Известная отсутствующая ERRATA — отдельный пробел, не повод чинить источник.

Готовность критерия требует ссылок на реализацию и воспроизводимые доказательства; не обещать баллы.
В конце сообщить изменённые файлы, команды/вывод, границы проверки, нерешённые вопросы и следующий стык.
Использовать `docs/templates/HANDOFF.md`.

## Git и безопасность передачи

Архив — самостоятельный snapshot без .git; исходный ZIP не изменён.
Не распаковывать автоматически поверх существующего Git с gitlink.
Читайте `docs/IMPORT_AND_GIT.md`: .gitmodules в исходном архиве ЕСТЬ, старое замечание устарело.
Не удалять .git, не выполнять reset --hard/clean, не переписывать историю и не делать push без разрешения.
При обновлении reference сначала согласовать источник, diff и provenance; не делать скрытый git pull.

## Правила добавленного frontend

Не редактировать `frontend/src/api/schema.d.ts` вручную: генератор `tools/generate_frontend_types.py` читает OpenAPI. Сохранять неизвестные поля плана и optimistic expected_revision. Не добавлять в браузер бизнес-формулы. SVG рассчитывает только координаты готовых рядов; Plotly исторически рассматривался, но не входит в зависимости этого среза.

После правок: frontend tests + typecheck + Vite build; backend pytest; OpenAPI/type generation checks. В текущей офлайн-поставке эти проверки имеют разный статус — читать отчёт, не копировать число passed из старого сообщения. `prebuilt` не перегенерировать фиктивным manifest: после правок выполнить штатную сборку в dist либо реальную альтернативную компиляцию `node frontend/scripts/build-portable.mjs`; второй путь не считается полным typecheck/Vite. Не подменять происхождение результатов на verified.

Проверять ограниченное число действий на экране, keyboard/focus/reduced motion, узкое окно. Исторические задачи T04/T06 не разрешают менять математику без отдельного задания владельца.

## Compact UI — актуальный срез

Один основной экран без sidebar: Infrastructure / SupplyMatrix / ResultPanel. Подробная передача — docs/frontend/HANDOFF.md. Не добавлять четыре страницы обратно. Матрица не суммирует коллизии; source_id, неизвестные поля и будущие периоды сохраняются. Выключение инвестиции не удаляет заказы. Кнопка «Оба» вызывает реальный stateless /api/calc для тех же решений, а не создаёт фиктивный RunRecord. Даты финансирования/ввода не изобретать из неоднозначного поля year. UI screenshot не является источником числовых данных модели.
