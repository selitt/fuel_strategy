# Служебные команды рабочего пространства

`workspace.py` использует стандартную библиотеку Python. Остальные инструменты могут требовать зависимости приложения. Актуальная установка описана в [README](../README.md).
Из корня:

```bash
python3 tools/workspace.py check
python3 tools/workspace.py status
python3 tools/workspace.py sources
python3 -m unittest discover -s tests/workspace -v
```

Для изоляции от посторонних startup/site-пакетов можно добавить `-S` сразу после Python:
`python3 -S tools/workspace.py check`.

`--root` позволяет проверить другую распакованную копию; `--json` возвращает JSON.
Команда ничего не пишет, не скачивает, не устанавливает и не исправляет автоматически.
Проверяются 8 областей: структура, рабочая копия входов, переносимость путей/Git,
зависимости задач, ссылки критериев/направлений, связи приёмки/вопросов, синтаксис JSON и новая Markdown-навигация.

Не проверяются бизнес-формулы, безопасность реальной миссии, научная обоснованность стратегии, работоспособность frontend,
полная семантика JSON Schema, внешние ссылки или свежий clone настоящего remote.
Оригинальные ссылки организатора и оба reference snapshot сохранены; известные пробелы зарегистрированы отдельно.

## Контракты и браузерный пакет

- `python tools/export_openapi.py --check` — сверка опубликованной OpenAPI с API.
- `python tools/generate_frontend_types.py --check` — сверка типов frontend с опубликованной схемой.
- `python tools/verify_prebuilt.py` — контроль исходников и assets portable-пакета.

Без `--check` первые две команды перезаписывают генерируемые файлы; это отдельное действие при согласованном изменении API. `tools/tool-versions.env` содержит рекомендации bootstrap, а не lockfile Python/npm-зависимостей. `.python-version` и `.node-version`, если добавлены командой, имеют приоритет.

Проверка Linux-хоста без установки: `./scripts/prepare.sh --check`. Явный запуск без `--check` может установить недостающие host-инструменты и зависимости; этот скрипт не запускает сервисы.
