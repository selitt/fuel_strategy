# Импорт и Git

Рабочая директория уже является репозиторием проекта. Не удалять `.git`, не
распаковывать поверх него новый архив и не выполнять `reset --hard`, `git
clean` или переписывание истории.

## Сохранённые snapshots

`.gitmodules` регистрирует два исходных snapshot-каталога:

- `fuel-hackathon/test_oil` — нужный кейс, commit
  `cec6de1950276091689e71a67f9a875fb4ca6213`;
- `fuel-hackathon/test` — другой кейс, commit
  `3fa773b8e416f814634ad3b017a3a2cbcabc3331`.

Оба каталога сохраняются полностью и не используются как место для рабочих
правок. Рабочая копия входов находится в корневом `data/`; `python3
tools/workspace.py check` сравнивает её побайтно с `test_oil`.

## Рабочая структура

- `data/` — CSV, сценарии, схемы, примеры и контрольные случаи для API;
- `docker/` — Dockerfile, Compose и пример локального окружения;
- `.local/projects/` — локальное runtime-хранилище JSON-проектов, не часть
  переносимого комплекта;
- `docs/`, `tasks/`, `prompts/`, `plans/`, `configs/`, `contracts/` — текущая
  навигация и рабочие договорённости команды.

Исходные PDF остаются в `docs/Task/`. Производные текстовые извлечения,
исторические отчёты и сгенерированные evidence-файлы удалены, чтобы в корне
оставались актуальные материалы.

## Передача изменений

Перед передачей проверить `git status`, просмотреть diff и отдельно убедиться,
что submodule не получил изменений. Не смешивать очистку с обновлением входного
snapshot или расчётной модели. Новую версию источников сначала получить,
сравнить и согласовать; затем явно обновить `data/` и проверки.

Git remote, commit, push и операции с GitHub выполняются отдельно и не являются
частью очистки рабочего дерева.
