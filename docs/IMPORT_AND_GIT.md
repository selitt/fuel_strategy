# Как открыть архив и не повредить существующий Git

## Рекомендуемый путь — отдельная папка

Распаковать ZIP в новую папку, открыть `fuel-workspace` целиком. Начать с START_HERE.
PDF, CSV, YAML и исходные README уже включены; повторный clone не требуется для старта.
В этом ZIP нет `.git`, личных настроек, ключей, виртуального окружения или node_modules.

Это **новый переносимый снимок**, не патч к Git-истории.
При желании продолжать как отдельный репозиторий после проверки файлов команда сама выполняет `git init`,
назначает remote и делает commit. Этот архив ничего не публикует и не меняет права.

## Продолжение существующего репозитория

**Не распаковывать весь новый архив поверх старого `.git`/gitlink.**
Сначала сохранить рабочие изменения и проверить diff/status в своей копии.

Минимальный перенос без смены устройства Git:
сохранить старые `.git`, `.gitmodules` и вложенные Git-репозитории;
добавить новые docs/tasks/prompts/contracts/configs и документированные области src/tests;
отдельно просмотреть замену README/.gitignore/.gitattributes.
Байты справочников совпадают с переданными исходниками, поэтому перезаписывать их не нужно.
При конфликте файла сохранить обе версии и разобрать diff; не удалять работу участника автоматически.

При таком пути `sources.lock.json` подтверждает обычные исходные файлы, а не состояние Git-индекса.
Проверка каркаса допускает зарегистрированные `.git` внутри двух известных справочных каталогов.
Она не заменяет проверку свежего clone и корректности ваших submodule URL/commit.

Перевод gitlink в обычные файлы — отдельная согласованная Git-миграция с резервной копией, проверкой индекса,
истории и свежего clone. Архив не содержит автоматического destructive скрипта такой миграции.

## Обновление источников

Не делать незаметный git pull и не перезаписывать CSV ради прохождения плана.
Сначала отдельно получить новую версию, сравнить изменения/уточнения, согласовать baseline,
затем обновить provenance/lock и зависимые тесты.
Не переносить из `test` чужой case_core.py или ограничения на4 лота.

Официальное описание различий: [Git submodules](https://git-scm.com/docs/gitsubmodules).
Наш выбор snapshot — удобство доставки каркаса, не требование кейса.
