## Порядок доказательства

Сначала независимый ожидаемый результат и вход; затем настоящий вызов модуля/приложения;
затем фактический вывод, сравнение в раскрытой точности, версия и команда повтора.
Для отрицательного теста ожидаем **конкретную диагностированную причину**, а не любое падение процесса.

Синтетический пример проверяет реализацию, не качество выбранной конкурсной стратегии.
V01–V10 — только часть проверки. Нужны границы, неверный ввод, полный горизонт,
внутригодовые события, сценарии, сохранение, UI и экспорт.

Для каждого критерия связать код/метод, вход, результат, проверку и артефакт защиты.
Реестр [criteria.json](regulation/criteria.json) не содержит самооценок баллов.
`not_started` меняется только после фактической реализации; evidence заполняется путём/запуском, а не обещанием.

## Проверки каркаса отдельно

`python3 tools/workspace.py check` проверяет исходные файлы, навигацию, структуру реестров и зависимости карточек.
`python3 -m unittest discover -s tests/workspace -v` проверяет сам служебный инструмент.
Ни одна из этих команд не запускает математическую модель и не доказывает выполнение A01–A13.
