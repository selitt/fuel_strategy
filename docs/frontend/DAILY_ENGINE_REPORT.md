# Дневной интерфейс и подключение SimulationEngine — 19.09.2026

## Результат

Основной экран: компактная строка хранилища, матрица пяти поставщиков на шесть лет и большой дневной график. Инвестиции Lunar-ISRU/Earth-New находятся в строках поставщиков. Дублирующая лента удалена. Оформление чёрно-серое; поступления и дефицит имеют смысловые маркеры.

Зелёный маркер поступления можно перетащить по оси дней: открывается предложение переноса с исходным/новым днём и объёмом. Это явно обозначенный макет согласования; он не отправляется на сервер, не сохраняется как решение и не меняет расчёт. Ползунок в диалоге уточняет предложенный день. Для рабочего переноса нужен контракт владельцев модели.

График показывает фактический `inventory_trace` выбранного года, недельную сетку условного 365-дневного календаря и два ряда в режиме «Оба». Выбор дня открывает увеличенный участок ±14 дней с точными значениями ответа API. Это не гражданские календарные даты. Дневные поступления совокупные: движок не возвращает их распределение по поставщикам.

`CalculationService` подключён к существующему `SimulationEngine(CaseCatalog(reference_dir))`. Файл `src/engine/pseudo_engine.py` удалён. Математика остальных файлов движка не менялась. Метаданные идентифицируют SimulationEngine и хэш кода/входных CSV/YAML; результаты прежнего движка становятся stale, проекты сохраняются.

Кнопка «Анализ рисков» вызывает новый `POST /api/calc/risk` только по нажатию. В режиме «Оба» выполняются два последовательных вызова на одном снимке решений. Во время анализа обычный предпросмотр приостановлен; после завершения применяется последний изменённый план. Устаревший снимок помечается. Ошибка второго анализа сохраняет первый ответ.

Диалог показывает фактическую сводку Monte Carlo (сейчас 100 прогонов, seed 42; «успешные» означают отсутствие дефицита и других нарушений), отдельно — дневную траекторию обычного расчёта. Индивидуальные случайные события и траектории движок не возвращает. Они не выдумываются. Обычные запросы не запускают Monte Carlo.

Сохранён latest-only планировщик с интервалом расчётных циклов не менее 100 мс. Геометрия графиков использует общий demand-driven requestAnimationFrame; числа и подсказки берутся из ответа, reduced motion отключает переход. Цель около 60 кадров/с не является гарантией на любом устройстве.

## Фактические проверки

- Frontend: 56 tests passed; полный TypeScript check и Vite build прошли.
- Полный `python -m pytest -q`: 164 passed, 27 subtests passed; прямое сравнение SimulationEngine/API, 2190 дневных строк, реальные Monte Carlo-вызовы.
- OpenAPI и generated frontend types актуальны; маршрут использует существующие DTO.
- Native Chromium (Vite и portable): по 26 проверок, включая реальное перетаскивание даты без отправки, дневные значения, модальное окно, последовательные риски, изменение решений во время анализа, частичный отказ, сохранение/экспорт/перезагрузка, узкое окно, keyboard focus и отсутствие runtime errors.
- Точные результаты браузера и снимки: [evidence/daily-engine](evidence/daily-engine/).

Воспроизведение браузера: `python tests/web/daily_smoke.py --site frontend/dist`; для portable — `--site frontend/prebuilt --artifacts frontend/test-results/daily-portable`. Нужны локальные Playwright/Chromium и доступные системные библиотеки. Скрипт использует временное хранилище и завершает собственный сервер.

На desktop приоритет сохранён; мелкие недельные подписи на телефоне не дорабатывались по последнему указанию пользователя.

`compact_smoke.py` и `live_smoke.py` описывают прежнюю компоновку с лентой; их старые результаты не подтверждают текущий интерфейс. Проверки сохранения неизвестных полей/коллизий продолжают покрываться чистыми frontend и API тестами.

## Границы и следующий стык

Математическая конкурсная приёмка, Docker/deploy и целевые пользовательские устройства не проверены. Сценарная логика существующего движка не полностью управляется YAML. Его `assumptions_reference` указывает на отсутствующий `docs/CASE_RULES.md`. Политика неизвестных сценариев/источников/лет остаётся задачей владельца модели: текущий движок может их игнорировать. Эти ограничения не исправлялись формулами во frontend.

Следующий стык с владельцами модели — согласованные календарные даты, источник каждого поступления и реальные истории адаптивных событий. До появления такого контракта интерфейс показывает только переданные результаты.
