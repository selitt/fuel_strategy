# Архитектура компактного рабочего места

Браузер → существующий `/api` → FastAPI/ProjectService/CalcService → прежний engine. Новый frontend не вводит расчётных endpoint, таблиц БД или формул. Backend-снимок побайтно сохранён.

## Компоновка

`App` управляет одной рабочей сценой, меню и диалогами. `Infrastructure`, `SupplyMatrix`, `ResultPanel` используют один `useWorkspace`. На узком экране CSS показывает план или результат; это не копии данных. Проект может открываться через query `project`. Унаследованные view-параметры не создают новую навигацию.

Матрица преобразует каталожные алиасы в визуальные строки без нормализации исходных идентификаторов. `readCell` возвращает индексы всех совпавших записей. При коллизии компактное поле заменяется входом в полный редактор. `writeCell` правит ровно одну запись, сохраняя остальные поля. Источники и горизонт расширяются из плана/каталога.

## Состояние и запись

Draft отделён от ProjectDTO. «Рассчитать»: валидация формы → создание или PUT с expected_revision → POST project calculate с актуальной ревизией → новый ProjectDTO → результат. На время операции повторный запуск заблокирован. 409 не повторяется автоматически и не перезаписывает чужую версию. Перед сменой проекта/импортом есть guard; при закрытии окна — beforeunload.

Изменение входов скрывает старые графики немедленно. Изменение названия не меняет физический результат. Выгрузка результата доступна только из сохранённого текущего состояния. Ошибка валидации показана явно, отрицательные/неполные поля не молча обрезаются.

## Сопоставление

Режим «Оба» запускает существующий stateless POST /api/calc для копии тех же решений с противоположным стандартным scenario_id. Второй ответ хранится в hook с basis-планом, не маскируется под RunRecord. Изменённый basis делает пару недоступной. Отдельное действие сохраняет второй сценарий серверным проектом. Старый endpoint сравнения сохранённых результатов также остаётся доступен в диалоге.

JSON сопоставления содержит primary_run, basis_plan, other_plan, other_result и other_origin. CSV берёт готовые значения, единицы и полный snapshot из двух ответов; у stateless результата нет придуманного run_id/hash. Серверные JSON/ZIP-CSV остаются неизменными. CSV escaping сохраняет существующую защиту от формул.

## Графика

AnalyticsChart рисует готовые годовые ряды; отсутствие значения разрывает линию, ноль сохраняется. FinanceChart визуализирует компоненты отдельно и не подменяет reported total их суммой. Отрицательные компоненты рисуются ниже нулевой линии. ServiceRing показывает отдельно общий и критический сервис; это не вероятность надёжности.

ResizeObserver подстраивает SVG viewBox под реальную рабочую область. Выбранный год управляется стрелками, slider и клавиатурой на графике. Цвета дополняются подписями/линиями/числами. Неизвестные единицы скрывают графики с фиксированными подписями, но исходный JSON доступен.

## Поставка

Стандартный путь — TypeScript check + Vite → frontend/dist. Доступный offline-путь — настоящий transpileModule + CommonJS linker + унаследованный React runtime → frontend/prebuilt. Manifest содержит hashes исходников и assets, а run.sh отказывается обслуживать старый пакет при их несовпадении. Offline сборка не считается полным typecheck.

Один HTTP-процесс обслуживает site и API. Docker/Python entrypoints и конфигурация доступа сохранены. Без credentials рабочее пространство открыто всем с сетевым доступом; для публикации задаются общий пароль и TLS на reverse proxy. Проекты — на постоянном volume, один worker. Проверки среды и ограничения перечислены в TEST_REPORT.md.
