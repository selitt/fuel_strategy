# Команда из пяти: границы параллельной работы

Это **предлагаемые направления**, не назначение людей по неизвестным навыкам. Стек и форма UI уже согласованы; имена, навыки и сроки согласуются в T00.
Машиночитаемая карта — [tasks/team.json](../tasks/team.json).

Для проверки подготовки каждому направлению выдана отдельная [валидационная handoff-карточка](handoffs/): W1, W2, W3, W4 и W5. Это задания на фактическую проверку своей машины и своей зоны, а не подтверждение реализации приложения.

| Направление | Ответственность | Основные задачи |
|---|---|---|
| W1 | Физическая модель и сроки | T02 |
| W2 | Контракты, инвестиции, экономика | T03 |
| W3 | Форматы, данные, сборка, сохранение и экспорт | T00, T01, T06 |
| W4 | Рабочее место оператора | T04 |
| W5 | Исследования, риски, научная база, сбор материалов | T05, T07, T08 |

**Тесты и описание своего метода пишет каждый.** W5 не становится единственным тестировщиком или автором всей записки.
Разделы защиты строятся из доказательств владельцев, а не из устных обещаний.

## Правила соединения

Сначала T00 и общий контракт T01. Затем физика, экономика, UI и методика могут идти параллельно.
Общая модель времени и формат результата имеют одного согласующего, но согласуются всеми потребителями.

Не делить разработку на «BASE у одного, STRESS у другого» или «каждому по поставщику».
Это создаёт дублирующиеся формулы. Различия каналов и сценариев проходят через одно ядро.

Ранний интеграционный срез проверяется ещё до завершения всех функций T02/T03/T04.
Для полных экспериментов T07 нужен законченный совместный T06.

## Работа с Git и агентами

У каждой задачи свой владелец, ограниченный scope и отдельная ветка/рабочая копия.
Не запускать двух изменяющих агентов в одной рабочей директории над одним файлом.
Общие contracts, календарь, корневой запуск и зависимости менять только после согласования потребителей.
Конкретный workflow веток выбирается после проверки среды команды; архив сам не создаёт remote/PR и не делает push.

После задачи: изменённые файлы, проверенные команды и фактические результаты, затронутые критерии, незакрытые вопросы,
изменения контракта и следующий стык. Использовать [шаблон передачи](templates/HANDOFF.md).
