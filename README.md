# Контур · Топливное планирование

Рабочее место оператора для кейса **«Топливный космоконтур 2035»**: редактирование плана, запуск расчётного адаптера, обзор результатов, сравнение и перенос проектов. Полный проект построен поверх `fuel_frontend_full.zip`, основанного на `11.zip`. Текущий срез — компактный одностраничный интерфейс.

**Один рабочий экран:** инфраструктура слева, матрица заказов и брони в центре, интерактивные графики справа. Нет бокового меню, отдельной страницы обзора и сетки карточек. BASE выбран по умолчанию; существующий STRESS и сопоставление одинаковых решений доступны в верхней строке. На небольшом экране переключатель «План / Результат» вместо трёх узких колонок.

Для исходных пяти каналов и шести лет основное содержимое проверено без вертикальной и горизонтальной прокрутки страницы на 1440×900, 1366×768 и 1280×720. На телефоне и для расширенного набора допустима локальная прокрутка таблицы; подробности открываются в диалогах.

Нет отдельной регистрации, внешних ключей и выдуманных KPI. В текущей поставке остаётся исходный `pseudo_engine`: это не подтверждённая математическая модель. Новый код модели не был приложен к запросу.

## Быстрый запуск без Node.js

В архиве есть готовый браузерный пакет. Python 3.13 рекомендуется для совпадения с проверенной средой.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
./run.sh
```

Открыть **http://localhost:8080**. Приложение и `/api` обслуживаются одним FastAPI-процессом. `run.sh` сначала выбирает обычный `frontend/dist`, а при его отсутствии проверяет контрольные суммы `frontend/prebuilt`. Изменённые исходники не будут молча обслуживаться старым пакетом.

Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.ps1
```

PowerShell-скрипт подготовлен, но не исполнялся в Linux-среде проверки. `depend.sh` / `depend.ps1` и `API_README.md` сохранены для прежнего backend-only процесса; для сайта используйте инструкции здесь.

## Docker

Из корня, где находится новый `compose.yaml`:

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f web
```

Это стандартная сборка из TypeScript через Vite. Нужен доступ к Docker Hub, npm и Python package index. Образ работает не от root; один процесс обслуживает сайт и API; проекты сохраняются в named volume `project_data`. По умолчанию наружу привязан только `127.0.0.1:8080`.

Вариант без npm: в `.env` задайте `FUEL_DOCKERFILE=docker/Dockerfile.web-prebuilt` и выполните ту же команду. Этот образ использует поставленный браузерный пакет; Python-зависимости и базовый образ всё равно должны быть доступны для загрузки. После правок frontend используйте обычный Dockerfile или пересоберите portable-пакет по инструкции ниже. Старый пакет с новым manifest без компиляции недопустим.

**В этой среде Docker не установлен, registry.npmjs.org не разрешается через DNS.** Docker-сборка и штатный `npm run build` здесь не прошли проверку запуском. Реально выполненные проверки и точные ограничения перечислены в [отчёте](docs/frontend/TEST_REPORT.md). Не путайте проверенный браузерный пакет с проверенной Docker-сборкой.

## Разработка frontend

Node.js **22.12+**; в package.json разрешены ветки 22–24, для воспроизведения этого среза используйте 22. Все прямые зависимости зафиксированы в `frontend/package.json`.

```bash
cd frontend
npm install
npm test
npm run typecheck
npm run build
cd ..
./run.sh dev
```

Vite: http://localhost:5173, backend: http://127.0.0.1:8000. Vite проксирует `/api` — домен backend не зашит в исходники.

Первый `npm install` создаёт `package-lock.json`. Его надо добавить в Git; далее использовать `npm ci`. В поставке нет выдуманного lockfile: транзитивные зависимости здесь не удалось разрешить через сеть. Dockerfile сам переключится на `npm ci`, когда файл будет в проекте.

После изменения веб-контрактов:

```bash
python tools/export_openapi.py
python tools/generate_frontend_types.py
```

Расчётный DTO и адаптер меняет их владелец, не frontend. У клиента нет своих формул топлива, экономики или прогнозирования.

## Пересборка поставленного portable-пакета

При доступном установленном TypeScript, но без Vite:

```bash
node frontend/scripts/build-portable.mjs
python tools/verify_prebuilt.py
```

Этот альтернативный сборщик действительно компилирует TS/TSX и связывает их с поставленным React 18.2 из `frontend/vendor/`. Он пересоздаёт JS, CSS, HTML и контрольные суммы. Он **не заменяет** полный `npm run typecheck` и не называется Vite-сборкой. Лицензии runtime включены. Внешние шрифты не загружаются.

## Команда / GigaIDE Cloud / публичная ссылка

Запускайте `./run.sh` в терминале workspace и публикуйте порт **8080** штатными средствами среды. Когда для проброса нужен bind на всех интерфейсах, задайте `FUEL_BIND_HOST=0.0.0.0`. Само наличие workspace не означает постоянный production-хостинг; поддержка Docker зависит от предоставленной среды. При отсутствии Docker работает обычный Python-запуск с поставленным пакетом.

Для Vite по внешнему preview-домену задайте `FUEL_DEV_HOST` равным **точному имени** этого домена (без схемы/пути). Не включайте `allowedHosts: true`. Для демонстрации предпочтительнее единый production-порт 8080, а не открытый dev-server.

Перед публикацией вне доверенной команды задайте в окружении **оба** параметра `FUEL_HTTP_USER` и `FUEL_HTTP_PASSWORD`, а TLS завершайте на reverse proxy платформы. Это один общий HTTP Basic-доступ, не пользовательские аккаунты. Не публикуйте пароль в Git. API, документация и UI закрываются вместе, кроме health endpoint. Без этих параметров доступ полностью открытый: все посетители видят и меняют одни проекты.

Скрипты `run.sh` / `run.ps1` читают окружение процесса, а **не** `.env`. `.env` автоматически применяется Docker Compose. Один worker обязателен для текущего локального JSON-хранилища; горизонтальное масштабирование требует отдельной работы над хранением и блокировками. Не запускайте несколько контейнеров поверх общего volume.

## Что уже работает

Матрица «источник × год»: в каждой ячейке отдельно заказ и бронь. Выбранная ячейка также редактируется ползунками и кнопками ±. Начальный запас, инвестиции и год — слева. Пропущенная запись не равна нулю. При совпадении нескольких записей они не суммируются: «Полные записи» открывает раздельное редактирование. Добавление/удаление строк и нестандартные поля остаются доступны там же.

 Создание, сохранение, повторное открытие, копирование и удаление проектов. BASE и MANDATORY_STRESS. Показатели и графики по годам, объяснения нарушений, раскрываемые таблицы. «Оба» выполняет два настоящих расчёта одинаковых решений, меняя только scenario_id, без автоматического создания второго проекта. Его сохранение доступно отдельно. Сравнение от двух до шести сохранённых результатов остаётся в меню. Импорт плана/проекта JSON, выгрузка планов и результатов JSON/ZIP-CSV, сравнения JSON/CSV, справочников CSV.

Защита от потери правок, ошибки 409 при конфликте ревизий, блокировка устаревших результатов, отсутствие нулей вместо неполученных данных. Вручную добавленные поля плана сохраняются. На мобильном таблицы прокручиваются внутри контейнера. Клавиатура, фокус и reduced motion поддержаны.

## Границы

`engine`, `calc_dto.py`, `calc_service.py`, `KosmoAPI.yaml`, данные и reference snapshots не изменены. Прохождение UI/API-тестов не подтверждает V01–V10, прогнозирование, оптимизацию и полноту модели. Нет редактора пользовательского набора CSV/XLSX: нынешний адаптер не принимает такой набор. Нет фейковых экранов рисков или прогноза; неполученные сведения явно отмечены в раскрываемых деталях. Приведённые расходы, если их нет в DTO, не высчитываются в браузере.
