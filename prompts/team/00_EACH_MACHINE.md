# 00 · Подготовка Linux-сервера для команды

**Кому:** владелец серверной обвязки. **Область:** Linux-хост и зависимости; код модели не менять.

## Промпт агенту

Помоги подготовить Linux-сервер для проекта «Топливный космоконтур 2035». Стек: Python/FastAPI + React/TypeScript/Vite + Docker Compose. Прочитай [корневой README](../../README.md), [инструкцию деплоя](../../docs/DEPLOYMENT.md), [общий маршрут](../../plans/README.md) и корневой `AGENTS.md`.

Сначала выполни только read-only диагностику:

```bash
./scripts/prepare.sh --check
```

Зафиксируй дистрибутив, архитектуру, shell, рабочий каталог, ветку и текущие изменения. Проверь Git, Python, uv, Node/npm, Docker CLI, работающий Docker daemon и Compose v2. Наличие команды `docker` само по себе недостаточно. Не останавливай чужие сервисы и не меняй системные настройки без отдельного разрешения.

После явного разрешения можно запустить `./scripts/prepare.sh` без `--check`: он может установить недостающие host-инструменты и зависимости на поддерживаемом Linux. Системный Python не заменять. Docker устанавливать по официальной инструкции конкретного дистрибутива; не открывать socket через `chmod 666` и не менять группы/права без согласия. При отсутствии сети, registry или привилегий зафиксировать реальную ошибку, а не обходить TLS или защиту хоста.

## Проверка проекта

Из корня проекта подготовьте серверное окружение:

```bash
cp docker/.env.example docker/.env
chmod 600 docker/.env
# заполнить FUEL_HTTP_USER и FUEL_HTTP_PASSWORD
docker compose --env-file docker/.env -f docker/compose.yaml config --quiet
docker compose --env-file docker/.env -f docker/compose.yaml up -d --build
docker compose --env-file docker/.env -f docker/compose.yaml ps
```

Откройте сайт через настроенный HTTPS reverse proxy либо локально проверьте `http://127.0.0.1:8080` и `http://127.0.0.1:8080/api/health`. Health подтверждает доступность процесса, но не математическую готовность модели.

Проверьте вход, открытие сайта, сохранение и повторное открытие проекта, расчёт, выгрузку и сохранность данных после перезапуска контейнера. После временной проверки разрешён обычный `down`; не использовать `down -v`, чтобы не удалить данные.

## Что вернуть

Короткий отчёт: дистрибутив/архитектура, версии инструментов, фактически выполненные команды, доступность сайта, проверка volume, блокеры и владелец следующего действия. Секреты и полный вывод `env` не показывать. Не объявлять прототип подтверждённой топливной моделью.
