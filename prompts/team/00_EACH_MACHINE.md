# 00 · Каждому участнику: подготовить свою машину

**Кому:** все пятеро. **Область:** только локальная среда. **Код и зависимости проекта не менять.**

## Промпт агенту

Помоги мне подготовить текущую машину для проекта «Топливный космоконтур 2035». Работаем на Python/FastAPI + React/TypeScript/Vite + Docker Compose, без Streamlit. Прочитай [общий маршрут](../../plans/README.md) и корневой `AGENTS.md`. По умолчанию сначала дай короткий план для обнаруженной ОС. После моего «выполняй» установи только недостающее в разрешённых пределах. Администраторские права, перезагрузка, принятие лицензии и вход в аккаунт остаются за человеком.

### А. До готовности общего фундамента

1. Определи ОС, архитектуру процессора, shell, рабочий каталог, ветку и текущие изменения. Различай Windows PowerShell и WSL: это разные окружения. Проверь Git, uv, Python, Node/npm, Docker CLI, работающий Docker daemon и Compose. Наличие команды `docker` само по себе недостаточно.
2. Проверь, что открыт командный репозиторий с `docs/`, `tasks/`, `src/`, а не исходный `test_oil`. URL/путь не придумывай. Если проект уже открыт — не клонируй его ещё раз. Если `.gitmodules` реально есть и материалы отсутствуют, прочитай его и предложи штатное получение submodules; ничего не удаляй. Для файлового snapshot это не требуется.
3. Предпочти уже установленные совместимые инструменты. Версии проекта возьми из `.python-version`, `.node-version`/`.nvmrc`, package.json и документа запуска, когда W3 их зафиксирует. До этого ориентир — Python 3.12.x и Node 24 LTS, а не «самая новая версия каждого пакета». Системный Python не заменяй.
4. Используй только официальные инструкции S1–S6 из README этого пакета. Не ставь Conda, Poetry, pnpm и Yarn дополнительно: договорились на uv и npm.

**Windows.** Работай в уже используемом окружении агента. Для нативной разработки подходят PowerShell, Git, uv и Node; Docker Desktop запускает Linux-контейнеры при выполнении его системных требований. WSL2 не нужно навязывать как место хранения исходников. Если проект уже в WSL2 — uv/Node и агент должны работать там, а Docker Desktop интегрироваться с этим дистрибутивом. Не дели одну `.venv`/`node_modules` между Windows и WSL. Не выполняй `wsl --unregister`, reset дистрибутива или переустановку ради настройки. Несовместимая ОС/недоступная виртуализация — явный блокер Docker, но не запрет нативной разработки Python/TS.

**macOS.** Определи Apple Silicon или Intel; используй подходящие установщики Node/uv и Docker Desktop. Homebrew допустим, если уже используется; не обязателен. Не навязывай Rosetta и `linux/amd64` проекту на ARM. Проверку Linux-сервера потом выполняем отдельно.

**Linux.** Определи дистрибутив; Docker Engine и Compose plugin устанавливай по его официальной инструкции, не выполняй Ubuntu-команды на любой системе. Рабочий Docker не переустанавливай. Не открывай Docker socket через `chmod 666` и не меняй группы/права без согласия: это привилегированный доступ.

**uv.** При наличии WinGet официальный вариант Windows — `winget install --id=astral-sh.uv -e`. На macOS/Linux официальный standalone-вариант — `curl -LsSf https://astral.sh/uv/install.sh | sh`. Сначала показать источник и проверить необходимость установки; не запускать скачанные скрипты без разрешения. Когда версия Python закреплена, `uv python install` в корне устанавливает запрошенный проектом интерпретатор. Не требуется активировать `.venv` вручную для `uv run`.

Если недоступен интернет, установщик, registry или привилегия — зафиксируй реальную ошибку. Не отключай TLS/антивирус, не меняй глобальные proxy и не повторяй бесконечные установки.

### Б. Когда W3 передал G0

Забери согласованный commit обычным командным процессом, сохранив свои изменения. Проверь наличие `pyproject.toml`, `uv.lock`, `frontend/package.json`, `frontend/package-lock.json` и файлов Docker. Если их ещё нет, останови только эту часть и сообщи «ожидается G0»; не создавай свои вместо W3.

В корне проекта:

```text
uv python install
uv sync --locked
npm --prefix frontend ci
uv run --locked python tools/workspace.py check
uv run --locked python -m unittest discover -s tests/workspace -v
uv run --locked pytest tests/smoke -q
npm --prefix frontend run typecheck
npm --prefix frontend run build
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Скрипты `typecheck`, тесты `tests/smoke` и Compose создаёт **01**; до G0 это ожидаемые команды, не уже готовые возможности архива. Не заменяй `npm ci` на обновление lock-файла при ошибке. Укажи конкретное несовпадение W3/W4.

Открой `http://localhost:8080` и `http://localhost:8080/api/health`, если W3 сохранил предложенные порты. В интерфейсе должен быть статус «расчётное ядро не реализовано», а не фиктивные показатели. При занятости порта согласуй локальное значение, не останавливай чужой сервис. После проверки разрешено `docker compose down`; **не использовать `down -v`**, чтобы не удалять данные.

### Что вернуть

Короткую таблицу: ОС/архитектура/shell, версии, фактически выполненные команды, что работает, что блокируется и кем. Секреты и полный вывод `env` не показывать. Общие файлы не менять. Результат своей ОС передать W3; успех на Mac не отмечать как успех Windows/Linux. После установки выбрать только свой файл 02–06.
