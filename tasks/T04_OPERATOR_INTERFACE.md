# T04 · Интерфейс по контракту, без подмены расчёта

**Направление:** W4. **Статус:** implemented_web_slice; математическая приёмка T06 отдельно.
**Зависимости:** T01. **Цель:** Подготовить контрактно совместимый пользовательский путь; настоящий расчёт подключается и проверяется в T06.

UI-срез реализован по отдельному разрешению пользователя. Передача: `docs/frontend/HANDOFF.md`. Фактические проверки: `docs/frontend/TEST_REPORT.md`. Добавление пользовательских dataset inputs и приёмка настоящей математики остаются в T06 / у владельца адаптера.

## Последовательность

1. Использовать утверждённую форму UI и контракт. Не вводить обязательную регистрацию, сторонний платный ключ или новый сервис без нужды.
2. Спроектировать ввод исходного набора/плана, заказов/резерва/инвестиций; в контроле защищать CASE_INPUT, исследовательские изменения явно отделять.
3. Сделать обзор спроса, поставок, запасов, потерь, стоимости, total/critical service, дефицита и конкретных нарушений.
4. Подготовить сравнение BASE/STRESS и планов, сохранение/открытие/выгрузку через согласованный адаптер, а не собственные формулы.
5. На этапе до ядра использовать только явно маркированные SYNTHETIC/NOT_CALCULATED фикстуры; кнопка не должна изображать успешный реальный расчёт.
6. Проверить ошибочный ввод, пустые/нерассчитанные состояния, процесс длительного расчёта, единицы и обозначения не только цветом.
7. Передать контрактно совместимый первый срез в T06; факт реального изменения KPI и совпадение экспорта принимаются совместно в T06.

## Приёмка

- Все действия имеют согласованные входы/выходы; экран не считает бизнес-математику.
- Фикстуры отделены от результатов, состояния/нарушения понятны. Завершение этой карточки само по себе не закрывает пользовательскую приёмку T06.

Связанные критерии: K19, K20.

## Передача результата

Назвать изменённые файлы, версию контракта, запущенные команды и фактический вывод; приложить воспроизводимые данные и ссылки на проверки. Отдельно перечислить что не сделано, блокеры и следующую зависимость. Шаблон: [HANDOFF](../docs/templates/HANDOFF.md).

## Короткий запрос агенту

> Прочитай AGENTS.md и `tasks/T04_OPERATOR_INTERFACE.md`. Выполняй только T04 в согласованном режиме: сначала проверь зависимости и предложи ограниченный план; к реализации переходи после разрешения. Опирайся на указанные первоисточники. Не решай соседние задачи, не меняй CASE_INPUT, не выдавай отсутствующие результаты за готовые. В конце отчитайся по приёмке с фактическими проверками.
